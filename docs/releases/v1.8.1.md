HGT elevation conversion now runs in the terrain worker, keeping the UI responsive while large terrain files are prepared. Terrain, camera and Livox data now have a shared rendering contract that can support additional graphics backends.

- **Terrain loading:** one preparation job per tile, acknowledgement before chunk generation, and recovery when the worker cannot start or fails. SRTM1/SRTM3 signed elevations and void samples are preserved.
- **3D resolution profiles:** Native, Balanced and Eco in SYS CONFIG, with a separate resolution limit for the 3D canvas. HUD and interface text retain the display resolution.
- **Rendering architecture:** backend-independent terrain, camera and point-cloud models; Three adapters own GPU resources. Terrain LOD changes preserve satellite textures, and Livox uploads only changed buffer ranges.
- **Diagnostics:** cumulative counts across rendering passes, CPU submission timing and a reproducible visible-window measurement command for developers.
- **Qt evaluation:** a separate Qt Quick 3D prototype reads versioned binary snapshots of the same terrain, camera and LiDAR data. The distributed GCS uses **Three.js/WebGL2**; the Qt prototype is excluded from installers.

Validation: HGT worker/fallback tests, rendering backend tests, data-contract and GPU-adapter tests, and Python/JavaScript packet compatibility tests all pass.

Installers: Windows x64, macOS Apple silicon and Intel, Linux AppImage and Debian/Ubuntu package. macOS and Linux assets are attached by GitHub Actions after publication.
